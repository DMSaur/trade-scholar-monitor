# 新增学者操作手册

往 `config/scholars.yaml` 补录新学者并配齐 ID、主页、领域标签的完整流程。
本手册沉淀自 2026-10-22 的 77 人批量补录,所有坑都来自实际翻车记录。

改本文件同目录下的 yaml 前,先 `git pull`;改完立刻 push。项目常有并行会话
和每日运行时同时写仓库,不同步会互相覆盖。

## 前置条件

- 网络:核验海外站点一律走本地代理 `127.0.0.1:7897`。直连会把被墙站点误判
  为不存在;反过来,S2 接口走代理即从 429 变 200。
- OpenAlex key 在 `.env`(每天 1000 次额度)。S2 只用匿名池,美国白天高峰
  限流,批量操作尽量在北京时间白天(美国夜里)跑。
- python 用 `~/.pyenv/versions/3.11.0/bin/python3`(requests、yaml、curl_cffi 已装)。

## 第一步:定名单

- 候选来源首选 Deardorff 家谱:https://websites.umich.edu/~alandear/tree/INDEX.HTM
  (约 1550 人,覆盖整个领域)。直连被 Cloudflare 拦,用内置浏览器打开等
  验证自动通过,再取 `document.body.innerText` 全量落盘。
- 筛选标准:仍在活跃发表、与现有名单互补。已故大师和名誉教授不会产生动态,
  不要加。
- 每人定三样:显示名(中文名学者用中文加 `name_en` 拼音字段)、机构、领域标签。
  领域标签现有六类:量化与理论、实证贸易、贸易政策、环境与历史、中国贸易、
  政策评论。

## 第二步:配 OpenAlex ID(主源,缺了就没有论文流)

搜索:`GET api.openalex.org/authors?search=名字`,带 `api_key` 与
`select=id,display_name,last_known_institutions,works_count`。

四个同名陷阱,按顺序防:

1. **消歧后缀**:档案名可能是 "Thierry Mayer B",姓氏匹配要用"任意 token
   等于姓氏",不能只比最后一个词。
2. **同名不同人**:先查机构 ID(`institutions?search=`),再用
   `filter=affiliations.institution.id:{ID}`(全历史)或
   `last_known_institutions.id:{ID}`(当前)过滤后再搜。
3. **机构滞后**:人换了学校,档案仍显示旧机构。以近两年论文的署名机构为准,
   必要时直接拉 `works?filter=author.id:X&sort=publication_date:desc` 看署名。
4. **没有干净档案**:部分国内学者在 OpenAlex 无可辨认档案,或档案被同名者
   污染( Works 数异常大)。宁缺勿错,留空只配 S2。

采纳标准:姓名 token 匹配 + 机构含预期关键词 + works_count 合理
(年轻学者 ≥15,资深 <500;异常大说明是合并污染档,配了会污染论文流)。

## 第三步:配 S2 ID(备用源 + 页面链接)

S2 的 affiliations 字段多为空,机构核验基本不可用;同名学者按 hIndex 最高
裸选会配错(真实案例:Jeffrey Frankel 被建议配到一位心内科医生)。

正解是**代表作反查**,脚本已封装:

```bash
python3 scripts/verify_s2_by_paper.py candidates.json report.json
```

原理:取学者 OpenAlex 档案里被引最高且有 DOI 的代表作,到 S2 按 DOI 单篇
查询,谁名下署名这篇论文就是谁;多个命中再批量比 hIndex 取主档案。
可断点续跑,report.json 里 status=ok 的自动跳过。

注意:入库前对全表做一次 ID 唯一性审计(两人不得共用一个 ID);报告里
status 为 no-author 或 title-not-found 的,查一遍同名档案的论文主题再决定
置空还是手工配。

## 第四步:主页核验

脚本已封装:

```bash
python3 scripts/check_homepages.py candidates.json result.json [--search]
```

核验标准是走代理拉页面后,标题或正文含学者姓名。只看状态码 200 会踩三个坑:

1. Google Sites 的 `site/XXX` 不存在时也返回 200(跳 Drive 登录页)。
2. 个人域名同形陷阱:evenett.com 是日本小说家的站,Evenett 真站是
   simon-evenett.com。
3. 直连会把被墙站点判死,误以为地址不存在。

`--search` 会对没有候选地址的人走 DuckDuckGo lite 端点自动搜索,需要
curl_cffi(impersonate="chrome")。搜索引擎的自动化限制要清楚:

- DuckDuckGo 按出口 IP 计数,每个干净 IP 只有 1-2 次请求的信任窗,冷却约
  1 小时,持续探测会刷新封禁。普通 requests 全被 202 挡死,curl_cffi 可用,
  节奏放慢(成功后间隔 8 秒,遇 202 退避 2 分钟),批量控制在几十个查询。
- Bing 的 `format=rss` 机械上零拦截,但对未登录会话的人名查询做相关性降级,
  实测命中率接近零,不建议用。
- Google 搜索在真实浏览器里几个查询后就出验证码。
- IDEAS/RePEc 全站被机器人流量压垮,搜索只返回空壳。

## 第五步:写配置并发布

yaml 字段:name、name_en(中文学者)、affiliation、field、added(补录日期,
作记录)、openalex_id、s2_id、twitter、homepage、enabled。

发布流程:

```bash
git pull --rebase origin main && git push origin main
# 要立刻看效果,在运行时克隆里刷新页面:
cd ~/.trade-monitor && git pull --ff-only origin main
~/.pyenv/versions/3.11.0/bin/python3 scripts/build_site.py
git add -f docs/index.html docs/data/latest.json
git -c user.name=Dimo -c user.email=21300680261@m.fudan.edu.cn \
  commit -m "页面刷新:..." && git push origin main
```

运行时克隆没有 git 身份配置,手动提交必须带 `-c` 参数。GitHub Pages 的
`data/latest.json` 有 CDN 缓存,验证线上数据要加 `?v=时间戳` 参数。

页面侧:学者名单自带领域筛选与六类标签展示,新学者只要 field 填了就会
出现在对应筛选里。

## 真实翻车案例

- 陆毅配成伊利诺伊大学同名化学家(871 篇),刘青配成工程师:OpenAlex 同名,
  机构过滤后才纠正。
- Galle 配到一个 554 篇的合并污染档:works_count 异常大就是信号。
- Frankel 的 S2 被建议配成心内科医生:hIndex 裸选的产物,代表作反查救回。
- evenett.com 是日本小说家站:主页必须核对姓名。
- "Thierry Mayer B":消歧后缀挡住姓氏匹配。
- Andrew McCallum:两个库的主档案都被同名的 UMass NLP 教授占据,两项置空,
  否则他的人工智能会议论文会天天刷屏。
